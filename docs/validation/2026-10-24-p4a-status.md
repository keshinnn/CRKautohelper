## 真實失敗與修正

- 舊季預覽標題沒有樓層，V1將預覽分類為MAP。V2改由獨立的選中綠框、未完成普通戰鬥圖示、當張地圖格與入口、右側普通難度、03:00計時器及啟用的進入按鈕確認。身份不由攻略意圖填入。
- 選中外框偶爾使一般六角候選漏格：僅在可見綠色連通元件符合當張格線位置，且橘色戰鬥圖示得分≥0.90、與次名差≥0.08時恢復；格線仍由影像獨立辨識。小幅圖示裁切對齊搜尋保留原分數門檻。
- 普通難度文字因星號與鏡頭移動導致OCR低分：重新對原始像素做有界裁切辨識，要求獨立讀出「普通」且得分≥0.95，保留原低分，沒有灌入預期文字。
- 第一次實際閉環停在區域1的第2531影格，原因是把「等待中的地圖」錯要求取得新的點擊權限。現在將只供等待的場景證據與可發新點擊的區域／座標證據分開；等待不重點，UNKNOWN仍停止，預覽身份仍須獨立確認。

初次失敗包保留於`artifacts/p4a-acceptance-01`；成功報告及完整五類工件位於`artifacts/p4a-acceptance-02/report.json`，辨識失敗前後packet保留於`p4a-analysis-01`與`p4a-analysis-02`。所有正例來源、人工操作區間及評分用框已先凍結於`data/p4a/cases.json`。

原候選中的隊伍設定、Boss與精英不計為這次普通節點正例。區域6點擊前入口被裁掉的案例保留為缺錨點候選，不冒充正例通過。篩選決定與時段逐項記於凍結標註，不刪除舊失敗。

## 可重現命令

在V2根目錄，以既有Python環境執行：

```
python -B ml/freeze_video_cases.py data/p4a/cases.json 新的原圖目錄
python -B ml/analyze_cases.py 原圖目錄/manifest.json 新的辨識目錄
node scripts/accept-replay.cjs 辨識目錄/manifest.json data/p4a/cases.json 新的驗收目錄
```

輸出目錄必須不存在，不覆寫歷史紀錄。`--cache`只可重用相同原圖綁定的V1 packet並重跑當前V2身份辨識；此模式不作完整新鮮處理效能的證據。P4-A本次V1 packet來自原始影格實際辨識，後續失敗修正重跑V2像素驗證與整個交易。

## 邊界與後續

這5段只有一種原始解析度、第一層、兩個欄位。不同樓層、比例、裁切、完整負例集合、p95效能與真實滑鼠送達都不能由本結果推論。初始baseline所列2384檔hash未變，未改V1正式流程。

下一階段P4-B使用同5段的75%、100%、125%，共15段；100%保留原PNG bytes。之後才是P4-C的30段、三次隨機變換及正式負例。P4-A/B不得標成G4合格，P5仍須另行批准。
