# CRK Helper V2 P4-A：五段原始影片閉環

> **For agentic workers:** Use superpowers:executing-plans and test-driven-development. 本階段連續執行，不等待額外批准；P5實機仍未批准。

**Goal:** 先以五段真實、不同互動的原始1440×1080影片完成地圖→節點→虛擬點擊→獨立預覽確認。保持原P0–P5與G0–G5。

**Architecture:** 只讀V1影像模組；在V2增加預覽選中外框像素證據與序列回放。人工標註只給評分器／虛擬dispatcher，不給辨識器。所有影格直接由原MP4解碼成原尺寸PNG，既有逐秒JPEG只作導航。

**Tasks / Expected results**

1. 核對並凍結五個真正普通戰鬥互動，逐幀記錄地圖穩定區間、人工點擊窗口、最早預覽與穩定預覽；記原始影片hash、frame index與PTS。排除隊伍設定／Boss／精英作為本次正例，但保留作負向診斷來源。Expected：五段非重疊真實互動，沒有把原候選直接當真值。
2. 先寫真實原圖測試再實作`ml/preview_identity.py`：獨立定位地圖格、唯一未完成戰鬥節點的選中外框、右側面板／計時器／進入控制項。缺少外框、面板、錨點或出現多個匹配時拒絕。舊季無樓層文字時從當張已錨定地圖定位絕對層數；禁止由intent/pending填身份。Expected：原圖正例可辨識，刪除／變更證據負例拒絕。
3. 以PNG+packet byte binding接入Node adapter及回放器。只在點擊時間窗口與落點正確時釋放人工後續影格；實際處理耗時與虛擬時鐘分開。每次錯誤保存五類工件、交易、來源與疊圖。遇UNKNOWN先修該失敗，不跳過。
4. 執行五段原始解析度，不執行縮放。通過後保存P4-A完整報告；不宣稱G4，不執行P5。接著才進固定75/100/125%階段。

**Pre-flight:** 原預覽adapter只接受帶樓層的標題，真實季4預覽僅顯示「戰鬥」；現有mapReview仍可取得地圖格，因此新增的身份判斷沿用同張像素定位，不更改V1、不重訓全部模型。未完成節點外框與已完成綠勾必須分開。
